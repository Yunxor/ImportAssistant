- 初次使用：先阅读第 1～3 节，按“配置范围 → 添加 FBX → 等待完整匹配 → 审阅选择 → 风险预检 → 更新 → 手动保存”执行。
- 配置命名规范：见[资产存放模板编写指南](G:/Projects/Perforce/WGame/Client/Plugins/ImportAssistant/Docs/ImportAssistant_StorageTemplates.md)。
- 查看实现与限制：见[实现方案](G:/Projects/Perforce/WGame/Client/Plugins/ImportAssistant/Docs/ImportAssistant_ImplementationPlan.md)。
- 排查无法勾选、版本时间、弹窗或零匹配：见第 9 节常见问题。
- 本文“当前功能”描述已实现行为；第 6 节明确已验证和未验证范围，第 8 节为后续工作，不应混同。

> **保存与覆盖是两回事。** 插件不自动保存或签出资产，但用户确认后会允许原生重导入覆盖已有未保存修改。执行前预检会加载本次所选资产及相关依赖，可能耗时和占用内存；普通列表检索不批量加载资产。

## 1. 打开窗口

重启项目编辑器，在 **FBX → FBX 资产导入助手** 打开窗口。FBX 是与 File、Tools 等同级的独立菜单，Tools 内不再注册旧入口；不设置相对 NAE、Help 或其他菜单的排列优先级。插件默认启用，无需修改工程插件列表；如果看不到入口，在插件管理中确认 Import Assistant 已启用。

本轮菜单源码已编译链接成功；首次链接的 DLL 占用在后台进程退出后解除，未强制结束进程。重启对应 DebugGame 编辑器即可使用新入口，现有自动化回归不包含新菜单点击和视觉验收。

当前生成的是 DebugGame 编辑器模块，需使用该项目对应的 DebugGame 编辑器启动。切换其他配置时需要重新编译该配置。

## 1.1 支持类型、筛选与兼容性

左侧“检索范围 → 资产类型”提供动画序列、静态模型、骨骼模型三个开关，默认全部启用，不能全关；改动后刷新。索引仅查询启用类，内存新增、删除、改名、来源/属性变化也覆盖模型。一份 FBX 可在同组同时列出对应的三类资产。

| 类型 | 原生导入数据 | 校验及范围 |
| --- | --- | --- |
| AnimSequence | Legacy `UFbxAnimSequenceImportData` / Interchange | 必须关联 Skeleton；Legacy 仅主来源；检查关键帧 |
| StaticMesh | Legacy `UFbxStaticMeshImportData` / Interchange | 不要求 Skeleton；Legacy 仅主来源；检查 LOD/顶点（包括 Nanite 顶点） |
| SkeletalMesh | Legacy `UFbxSkeletalMeshImportData` / Interchange | Skeleton 有效；Legacy 0/1/2 为完整/几何/蒙皮；分项来源需有基础几何；检查骨骼和 LOD 顶点 |

旧 ini 缺少类型字段时三类默认启用，想保持动画单类需关闭模型开关。原模板枚举值不变，模型类别从预留变为正式应用。不直接把 Skeleton、材质、纹理、PhysicsAsset、Montage 等作为独立 FBX 目标。Legacy 场景导入、自定义角色重导入工厂、独立 LOD 工具需使用原流程，不强行套用普通模型更新；Interchange 能力必须符合当前环境。

## 2. 检索

1. 在左侧 UE 属性面板中展开“资产目录”数组，添加目录项并通过内容目录选择器选择 `/Game/Characters` 等路径。支持多个目录及已挂载的插件内容，可选择是否递归，同时选择本次资产类别。
2. 启用“源路径匹配”或“名称关键词匹配”，也可同时启用。组合匹配取并集，而不是交集。
3. 在“忽略前缀”和“忽略后缀”字符串数组中逐项配置规则，不再使用分号分隔。按数组顺序移除第一个匹配项；关键词按下划线、短横线、空格、点分词，支持全部或任意关键词。
4. 源目录发生迁移时，每行填写一条 `旧绝对目录 => 新绝对目录`。映射只影响候选发现，检索时不修改资产。
5. 从资源管理器拖入 FBX，或点击“添加 FBX”。重复文件自动合并，非 FBX 文件忽略。每个文件生成独立小组，悬停组标题查看完整路径。
6. 等待状态显示索引就绪且后台匹配结束。后台匹配完成并通过版本校验后一次发布结果，不先发布可执行的半份清单；未完成时组内显示等待提示。配置变化或索引存在待合并事件时禁止执行旧结果。

在普通检索模式，索引变化会使旧结果失效并重新匹配；更新结束后的报告模式会保留原结果，当前状态列可刷新，再次执行会准确预检所选对象。两种模式都不会允许在未完成检索或正在预检/更新时修改执行选择。

右侧使用虚拟化树形列表，按 FBX 添加顺序排列小组，默认展开且可以折叠。组标题为不含扩展名的 FBX 文件名，Tooltip 为完整路径；同名但路径不同的文件不会合并。组内显示对应资产的路径、原来源、匹配依据和更新状态，点击资产名称可定位。零匹配 FBX 仍保留小组并显示提示，未完成检索不会误报零匹配；不再为无关的未知来源资产建立独立小组。刷新结果时保留已有小组的展开状态。

### 匹配结果与来源诊断

只有源路径、路径映射或名称关键词实际命中的资产才进入结果。缺少来源记录且名称无关的资产不会因为位于 `/Game` 或模板目录中就出现；也不会写成 CSV 中的资产匹配行。零匹配 FBX 的报告行仍保留。

关键词实际命中但来源未知的资产保留在对应 FBX 组，“匹配依据”显示关键词候选，Tooltip 列出真实命中的词。没有可确定的来源槽位时禁止勾选和执行，不自动绑定来源；“来源未知”不是匹配依据。

未命中任何本次 FBX 的未知来源资产仅在底部提示：“检索范围内另有 N 个资产缺少可用来源记录，未确认与本次 FBX 有关；不计入匹配结果。”数量按资产去重、按实际类型和目录范围过滤，不包含已经作为关键词候选展示的资产；未添加 FBX 时不统计。该诊断不代表这些资产一定同源，也不能证明它们一定无关，不会为此批量加载对象。

每个 FBX 小组拥有独立细灰边框和背景，边框覆盖组标题、模板说明以及组内全部资产。折叠时边框收缩并闭合到标题，零匹配小组也保留边框。标题、正文和组尾按可见行分段绘制，仍使用单层虚拟化列表，不为每个组创建嵌套资产列表。

“类型”列显示简洁的官方类型名称，例如 `Animation Sequence`；完整 UE 类名保留在 Tooltip 中。资产名称按钮与类型标签使用 `AssetDefinition` 提供的官方类型色，AnimSequence 为官方绿色；资产行使用淡色背景，状态文字保留原有颜色。类型名称与配色按类缓存，类型定义变化时使缓存失效，绘制时不加载资产对象；未注册类型使用灰色并保留真实类名。

悬停类型标签可区分资产类型、UE 类完整路径、资产格式 `.uasset` 以及实际记录的源文件扩展名（如 `FBX（.fbx）`）。缺少来源记录时明确显示未知源格式，不默认伪造为 FBX。三类资产混合展示并使用各自官方颜色，类型由真实类路径确定，不从前缀硬猜。

每个资产单元格左右各留 6、上下各留 3 个 Slate 单位，FBX 分组标题前额外增加 8 个单位留白。长资产名、路径、来源和状态使用省略号显示，并在单元格内部裁剪，不会占用相邻列的留白；完整内容可通过 Tooltip 查看。

悬停“匹配依据”的资产单元格时，显示本次检索记录的实际匹配内容：

- 关键词候选：全部 / 任意模式、实际命中的关键词、匹配的资产名称；已忽略的前后缀和未命中的词不会作为命中关键词展示。
- 源路径匹配：资产记录的原路径、解析后的路径和本次 FBX 路径。
- 路径映射：实际采用的映射规则、映射前后路径及本次 FBX 路径；有同优先级歧义时额外提示。
- 多种依据同时命中时分段显示；悬停不重新运行检索，也不加载资产资产。

文件和检索按钮位于结果区顶部第一排；选择与更新操作在其下方独立一排靠右排列，窗口较窄时可以换行。底部信息区只保留状态、进度、提示和“导出报告”按钮。

- **检索 / 刷新**：重新匹配当前 FBX。范围不变时复用已有索引，并更新内存资产信息；范围变化时自动重建索引，是日常入口。
- **重建索引**：从 UE 资产注册表重新构建插件自己的元数据索引后再匹配，用于怀疑插件缓存不一致时；不是强制扫描磁盘，也不重导入资产。
- **停止匹配**：取消当前匹配，过期结果不可用于更新；不停止资产重导入，也不强行中断引擎资产发现。
- **清空本次文件**：清空本次输入、匹配列表和选择，不删除 FBX 或 UE 资产。当前没有逐文件移除入口。
- **导出报告**：只导出当前结果，不更新或保存动画资产；更新进行中禁用。

设置类为 `UImportAssistantSettings : UObject`，声明 `UCLASS(Config = EditorPerProjectUserSettings)`；目录为带有 `LongPackageName` 元数据的 `TArray<FDirectoryPath>`，前后缀为 `TArray<FString>`，均使用 `UPROPERTY(EditAnywhere, Config)`。

配置通过 UE `SaveConfig` / `LoadConfig` 反射序列化，显式保存在 [插件配置文件](G:/Projects/Perforce/WGame/Client/Plugins/ImportAssistant/Config/ImportAssistant.ini)，配置节为 `[/Script/ImportAssistant.ImportAssistantSettings]`。文件首次打开窗口时生成；不存在时迁移旧用户配置中的 `ImportAssistant` 节，旧配置保留不删除。属性编辑完成后自动保存，搜索时也会重试保存。配置文件只读或写入失败时，左侧显示提示，当前内存设置仍可用于检索，不擅自签出或清除只读属性。将该文件纳入版本控制后，设置将随插件共享，个人源目录路径是否提交由用户决定。

后台匹配仅接收普通值类型快照，不访问设置 UObject。数组顺序和重复项可保留，清空数组后重新打开不会恢复旧值；空资产目录数组不能执行检索。

Windows 路径采用忽略大小写的比较策略；大小写敏感目录、符号链接和 UNC/映射盘身份等价未专门验收。

### 表头与分组三态选择

表头原“选”文字替换为全局勾选框，作用于所有 FBX 分组，包括折叠组中的可选资产。每个分组标题文字前也有勾选框，作用范围只在本组；原“取消选择”按钮已移除，右上仅保留“选择明确同源项”和“更新所选… / 停止更新”。

| 显示状态 | 含义 | 点击后的行为 |
| --- | --- | --- |
| 不勾选 | 作用范围内全部未选择；首次检索为此状态 | 全选可选资产 |
| 横杠 | 作用范围内部分可选资产已选择 | 取消该范围内全部选择，不是补齐全选 |
| 勾选 | 作用范围内全部可选资产已选择 | 取消该范围内全部选择 |

逐条勾选、组内操作和表头操作相互联动。折叠不影响组内选择；点击复选框会处理鼠标事件，不将该次点击作为展开/折叠操作。来源缺失、来源槽位歧义等不可选行不参与全选及三态统计；零匹配和没有可选项的小组保持未勾选并禁用。检索未完成、普通检索结果过期、配置变更、正在预检/确认/更新时不允许修改选择；批次结束且索引合并就绪后，即使保留报告也可以继续修改选择。

**多 FBX 来源冲突**：同一资产仍只能选择一个来源。全局全选不替用户决定来源，会跳过存在冲突的资产并提示去重数量；有其他选中项但冲突项仍未选时显示横杠。只有冲突项时，点击后仍保持未勾选并显示提示。组内全选视为用户明确选择该组 FBX，会自动取消其他组对同一资产的互斥选择；其他组中不相关资产不受影响。全局取消则同时取消这些已明确选择的冲突来源。

批量选择包含可选的关键词/路径映射候选，属于用户主动选择，不自动执行更新；来源改绑、覆盖未保存修改或非主来源槽位内容更新时按下述风险流程确认。原“选择明确同源项”仅选择无冲突精确同源行，作为更保守的选择入口保留。

三态读取使用全局和每组缓存的计数，逐项变化增量更新，不在每次控件绘制时遍历全部结果。互斥来源采用对象路径索引定位已选行，避免组内全选对每条冲突行反复扫描全部结果。重建分组时重新汇总并保留展开状态；选择不写入 Config，不影响 CSV 全字段导出。

### 自定义显示列

列表表头上方增加一行工具栏，左侧为已添加 FBX 数量和列表说明，右侧为小齿轮“显示列设置”。点击齿轮，在菜单中勾选或取消勾选以下信息列，对所有 FBX 分组统一生效：

- 类型
- 资产路径
- 原来源
- 匹配依据
- 自动重导入
- 是否脏数据
- 版本时间
- 状态 / 结果

“选择框”和“资产名称”固定显示，不提供隐藏操作。默认显示全部信息列；菜单中的“恢复默认列”可一键恢复。勾选操作不会立即关闭菜单，可以连续调整多列。

列切换立即更新表头及已生成资产单元格，剩余列按原相对宽度分配可用空间，不留下隐藏列占位。该操作不重新检索、不重建索引、不取消后台匹配，也不改变勾选状态、分组展开状态或既有更新结果；分组标题及其模板/监控汇总说明不属于信息列，不受此菜单影响。

显隐列表保存在现有插件 `Config/ImportAssistant.ini` 的 `HiddenResultColumns` 数组中，使用 `UPROPERTY(Config)` 和 UE Config 序列化，重新打开窗口时恢复。没有该字段的旧配置默认显示全部列。此字段只由齿轮菜单编辑，不在左侧检索面板重复展示；文件只读或写入失败时保留本次内存显示状态，并沿用配置错误提示，不主动签出。与现有插件配置相同，文件纳入版本控制后这些设置也会随插件共享。

列显隐仅影响界面；CSV 仍导出全部既有报告字段，隐藏“状态 / 结果”也不会改变更新或结果记录。

前两列固定显示，其余八个信息列可在齿轮菜单勾选显隐；旧配置中未列入隐藏数组的新列默认显示。

| 列 | 显示内容 | 悬停位置与重点 |

| 选择框（固定） | 全局三态框，资产行是单条选择 | 表头提示全局范围和冲突处理；分组框只作用于本组 |

| 版本时间 | 上次导入时记录的 FBX 修改时间，UTC | 单元格列出各来源槽位和时间；不是操作或保存时刻 |
| 状态 / 结果 | 选择状态或最近一次涉及该行的执行结果 | 报告模式重新勾选不覆盖结果，单元格显示完整说明 |

### 表头备注与单元格详情

所有信息列表头均提供字段备注，悬停列标题可查看含义及边界：资产名称解释点击定位；类型解释官方类型色和文件格式；资产路径区分 UE 包路径与磁盘源文件；原来源解释检索快照；匹配依据解释取并集及候选含义；自动重导入解释条件、独立保存与公开接口限制；脏状态解释未保存而非损坏；版本时间解释 FBX 版本时间而非操作/保存时间；结果列解释内存更新及报告保留。

资产单元格的 Tooltip 仅保留该条数据详情，不重复通用概念说明。例如版本时间仅列资产路径、各来源槽位和时间，脏状态只列具体目标资产/直接依赖及当前状态，自动重导入保留实际监控目录、过滤规则、关联来源和设置。匹配依据仍保留实际命中的关键词、路径或映射证据。齿轮菜单项复用对应字段备注，即使列已隐藏也能查看说明；隐藏后恢复列不会丢失备注。

备注为静态文本，单元格沿用现有值缓存；不会因悬停重新检索或加载资产。列顺序、相对宽度、勾选、匹配和更新行为均不变。字段备注分层不改变数据；0.2 在旧 14 列后追加类型和槽位两列共 16 列，详情字段精简为具体记录，不再为每行重复表头的通用解释。

### 是否脏数据

“是否脏数据”默认显示，并可通过齿轮隐藏。此处“脏”指资产包存在 UE 未保存修改，不表示数据损坏。检查当前资产包；动画/骨骼模型还检查 Skeleton，已加载模型检查直接引用的材质、PhysicsAsset、BodySetup 等依赖包。显示“否”“是：静态模型”“是：骨骼模型、骨骼”“是：关联依赖”等，动画仍使用动画/骨骼标签；静态模型没有 Skeleton 不算未知。单元格 Tooltip 列出具体脏资产的对象路径；共享骨骼变脏会反映在相关动画/模型行。只检查直接引用对象，不递归扫描全引用图，也不保证发现后端全部隐式依赖。

列表仅查询已加载对象/包及直接依赖，未加载对象通过类元数据及 Skeleton 字段判断可见状态，不为脏状态加载资产；未加载模型的材质和物理依赖可能不可见，点击执行后才形成准确风险清单。脏状态变化事件与索引版本触发有节流的缓存刷新；检索发布、批次结束和导出前也会刷新。列和 Tooltip 仅显示值缓存，不在绘制中扫描 UObject。执行前则加载本次所选资产并完成相关编译，准确形成风险计划。

### 版本时间

“版本时间”默认显示，可在齿轮菜单中隐藏；CSV 增加版本时间和详情。该时间来自资产 `AssetImportData.SourceData.SourceFiles[].Timestamp`，含义是 **上次导入时记录的源 FBX 修改时间**，不是点击重导入的时刻，也不是 `.uasset` 保存时间。示例 `2026-11-09 03:04:05 UTC`，显式标出 UTC 以避免本地时区歧义。

有明确来源槽位的行显示该槽位时间；表头 Tooltip 解释时间含义、读取来源和保存边界，单元格 Tooltip 仅展示资产、所有来源槽位与时间。多来源却没有确定槽位时不猜测主来源，缺失或零时间显示“未知”。不访问当前磁盘 FBX 来冒充已经导入的版本，也不以 uasset 文件时间替代。源文件在版本库中的提交时间、历史更新时间均不属于此列含义。

通过注册表来源 JSON 读取时间，索引快照保留所有槽位；检索阶段不加载资产。检索发布、索引元数据变化、批次结束和导出前更新显示，未保存资产使用当前内存导入记录。刷新不会替换报告的原来源快照或结果文字；如果导入后端未记录时间，插件不伪造时间或修改元数据补写。

默认关闭，不改变现有配置。启用后默认“模板目录优先，补查原资产目录”；仅模板模式会明确提示未检查目录外资产。分组标题下显示字段解析和目标目录，补查到的其他位置资产标记为“模板目录外候选”。资产是否匹配仍由原有源路径 / 关键词规则决定。

### 原生自动重导入状态

每条匹配资产增加“自动重导入”列，FBX 组标题下增加汇总。判断分成两步：

1. **FBX 监控范围**：目录监控总开关开启、路径位于实际活动目录内，并通过该目录当前配置的包含/排除通配符及原生导入格式过滤。`/Game/` 等虚拟目录按 UE 的规则转换为物理目录，不把无效配置当成有效监控。
2. **资产来源关联**：资产导入元数据中的真实来源能按原生源文件缓存语义解析到这份 FBX；检查所有来源记录，不只检查第一项。关键词相似或插件路径映射命中，不等于原生自动重导入关联。

`.uasset` 所在目录不需要另外受监控，也没有为本插件虚构“资产自动更新开关”。FBX 受到监控且资产的真实来源关联它，才显示资产“已启用”。

| 显示 | 含义 |
| --- | --- |
| 已启用 | 当前活动目录、配置规则和资产来源关联符合原生自动重导入条件 |
| 已启用（需确认） | 同上，但 UE 设置要求用户确认，不表示静默自动执行 |
| 未启用 | 总开关关闭，或当前 FBX 不在监控范围内 |
| 被规则排除 | FBX 位于活动目录内，但未通过包含/排除规则或工厂支持格式过滤 |
| 来源不关联 | FBX 受监控，但当前资产的真实来源不是它；例如只靠关键词找到的候选 |
| 无法确认 | 缺少来源信息、未取得活动监控、目录未生效、规则不可见或监控配置正在刷新 |

单元格 Tooltip 展示 FBX 路径、配置/实际目录、相对路径、过滤规则、资产来源记录，以及“处理前确认”和“启动时检测变更”设置；通用条件及能力边界移至表头备注。分组显示全部/部分资产启用及数量；零匹配会明确区分“FBX 受监控”和“本检索范围没有匹配资产”。统计仅针对当前组的匹配结果，不是全工程自动更新清单。

窗口每秒轻量检查实际目录和索引版本；仅在变化时更新状态，不重复扫描全工程、不加载资产对象。资产来源变化时重新读取注册表当前元数据，原结果中的“原来源”仍保留用于报告审阅。开始更新、导出报告前也重新评估。

**生效时序与可见性边界**：UE 5.8 原生监控在配置变更后至少延迟 5 秒，并等到自身空闲才重建。插件在窗口刚打开或监控范围/规则变更后的约 6 秒内显示“无法确认”，随后重新评估；这段观察期不是重建完成的证明。UE 公开接口只给出活动根目录，不给出实际运行时过滤规则、重置完成事件或待处理任务。编辑器繁忙、第三方工具覆盖同一目录过滤规则时仍需人工核实；无法读取规则的额外运行时目录不会被直接报成已启用。

“已启用”只表示按当前可见信息符合条件，不表示 FBX 已变化、已有更新任务、更新已完成或一定成功。是否检测关机期间的变化还取决于“启动时检测变更”。原生自动重导入有独立保存流程，不受本插件“仅更新不保存”约束；插件不修改 UE 全局开关，也不暂停或取消原生任务。

## 3. 审阅和更新

- 不自动勾选候选。“选择明确同源项”只选择精确路径命中、无来源冲突且具备明确来源槽位的资产。
- 关键词或路径映射候选由用户主动勾选。
- 多个 FBX 命中同一资产时，选择一行会取消该资产的其他来源选择。
- 来源槽位缺失或歧义的行禁止更新，先在资产编辑器处理来源。
- 点击“更新所选”会先加载**全部本次所选资产**、完成相关编译并持有预检所需对象；不是只加载当前正在重导入的一项。大批次可能增加内存和等待，建议按组或小批次执行。来源改绑、所选资产/直接依赖存在未保存修改或非主来源槽位内容更新时会确认；普通主槽位同源且干净直接执行。判断改绑使用原生导入后端解析的真实路径，统一相对路径、分隔符及 Windows 大小写，不直接比较显示字符串。
- 风险弹窗只列风险项：最多五项改绑及最多十个去重脏资产；完整原来源→本次来源与脏资产计划在有风险时复制到剪贴板。覆盖提示明确说明可能覆盖已有编辑内容、不自动保存或签出、不保证一次撤销。
- 确认后使用本次选中的 FBX；路径不同时会改绑来源，不会无提示地从旧路径导入。
- 只有本次勾选且可更新的资产中，存在判定为“已启用”的原生自动重导入关联项时，才额外提示可能重复更新及原生独立保存风险，并列出相关 FBX 与数量。不再仅因总开关开启就警告；未勾选、不关联、被排除和无法确认的项目不触发该警告。提示不是任务正在运行的证明，也不提供与原生任务的互斥锁。

右上“更新所选…”与停止更新共用同一按钮：

| 状态 | 按钮文字 | 行为 |
| --- | --- | --- |
| 空闲 | 更新所选… | 有有效选择时可用；执行前形成新计划，来源改绑、覆盖脏修改或非主来源内容更新时确认；取消确认不启动队列 |
| 更新中 | 停止更新 | 请求停止后续项目，不强行打断当前资产 |
| 已请求停止 | 正在停止… | 禁用按钮，等待当前资产处理结束 |
| 完成或已停止 | 更新所选… | 恢复勾选与更新入口；保留结果报告，允许直接选择下一批，执行时重新预检当前元数据与脏状态 |

用户主动停止后，尚未开始的项目标记为“用户取消，未执行”；因来源/状态变化中止或前项导入失败停止，会使用对应的未执行原因，不伪装为用户取消。已完成的内存修改不会撤销，也不会自动保存。没有独立的“取消后续更新”按钮。

更新串行执行，单个 Legacy FBX 重导入可能暂时阻塞 UI，停止操作需要等界面恢复响应。执行期间窗口不允许正常关闭。重导入队列由窗口 Tick 推进，执行时保持窗口显示，不要切换到隐藏页签或最小化后期待队列继续实时推进。

批次开始前已有未保存修改的目标资产或直接关联依赖不再因脏状态跳过，用户确认风险后允许原生重导入覆盖已有数据；不主动清除脏标记、不从磁盘重新加载旧版本，也不是先清空 Skeleton。具体覆盖/保留的数据取决于导入后端。

预检在所选对象加载、编译完成后形成包修订与脏状态快照，确认期间及每项执行前复核来源、适用的 Skeleton 关联和相关包变更。已脏的包再次编辑也会使旧计划失效，未确认的新修改或来源变化会中止批次并要求新计划；本项成功导入自身产生的共享包修改可由后续项使用。实际导入失败停止后续项目，不在失败数据上继续覆盖；缺文件等导入前失败会记录原因，未进入导入的失败项不自动污染其他项的执行许可。任何缺对象、导入数据、必需的 Skeleton（动画/骨骼模型）或无法确认来源槽位导致的预检错误都会阻止本次计划开始。

变更检测依赖 UE 修改/属性/事务/脏包事件和执行前状态校验；未发出事件、又未改变可见状态的直接内存写入无法被可靠识别。执行期间不要并行编辑相关对象或让其他导入工具写入同一批资产。

更新完成后，选择权限与执行权限分离，不再用“保留报告”永久禁用勾选。索引合并完成后可继续单选、全局/组勾选；改绑来源导致上批快照失效时，再次执行以当前内存真实来源形成新计划。选择及互斥取消不覆盖上批结果文字。普通检索模式仍拒绝过期快照，修改检索配置或启动检索后必须等待查询完成；预检/确认/更新期间仍禁用。未保存修改仍须按风险提示确认，不因连续操作绕过。

更新成功显示“已更新，未保存”。目标资产、适用的 Skeleton 和其他受影响包均保留未保存状态，由用户检查后通过 UE 正常保存流程保存。插件不弹出资产保存窗口，不主动签出，也不因目标 uasset 只读而阻止内存更新；保存时的权限、签出和冲突处理由 UE 与用户负责。插件设置的 Config 自动保存和手动导出 CSV 不受影响。

此改动不关闭 UE 自身自动保存、Auto Reimport 或其他第三方工具；需要完全手动控制落盘时，应同时检查这些独立功能。执行期间请勿并行编辑相关资产。

## 4. 导入配置与保存边界

- 复用原生重导入，不创建新的目标资产覆盖原对象。
- Legacy FBX 使用原有导入数据，调用期间暂时关闭 Interchange 转换，退出同步调用后恢复全局状态。
- Interchange 资产要求当前环境启用对应 Animations/Meshes 类别的 FBX 支持；不满足时跳过，不自动转换旧后端。
- 元数据保留空来源槽位和标签，避免把 SkeletalMesh 的槽位 2（蒙皮）压缩为 1（几何）。Legacy 动画/StaticMesh 仅支持主来源。
- Legacy SkeletalMesh 的 0/1/2 是完整内容/仅几何体/仅蒙皮权重，不是 LOD；非主槽位要求有效的基础几何。无法保证原生分项语义时拒绝执行，不静默切成完整导入。非主来源即使干净同源也提示具体更新内容；Interchange 不硬套 Legacy 语义。
- 同一 FBX 命中一个资产的多个来源槽位仍判歧义，本版没有额外槽位选择器，需先在原流程明确来源。
- 导入完成后等待编译，校验返回结果、目标来源、导入数据类型、适用的 Skeleton 关联，以及动画关键帧或模型 LOD/顶点数据；静态模型不依赖 Skeleton。内容无效会报告失败并停止后续项。
- 动画包、Skeleton 包和其他依赖包都不自动保存，不执行 Save All。结果报告列出需要检查并手动保存的相关包。
- 已移除“允许签出（不提交）”配置和插件主动签出逻辑；不检查目标包的写入权限，不清除只读属性。用户手动保存时由 UE 处理签出。
- 导入失败不保存。尝试恢复来源路径不等于回滚全部动画数据，失败后请检查未保存对象，必要时从版本控制恢复。
- 操作不是整批原子事务，已完成的内存更新不会因后续失败或取消自动回滚，也不会被自动保存。

Notify、Sync Marker、手工曲线、Additive、Root Motion、多 Take、各自截帧和采样设置是否符合预期，仍须用实际使用的导入后端和测试 FBX 回归验证。

## 5. 结果报告

完成后保留原结果列表，包括未勾选、已取消、失败和“已更新，未保存”的行，不自动用新查询覆盖报告。“状态 / 结果”保留最近一次涉及该行的执行结果，不追踪用户之后的手动保存；勾选可继续修改，当前“已选择”字段随操作变化。脏状态和版本时间反映当前元数据，因此报告不是不可变历史归档。再次更新所选行会替换这些行的执行结果，未参与的新批次行保留原结果。

“导出报告”保存 UTF-8 CSV，包含实际 FBX、资产路径、原来源、匹配依据、是否选择、结果、目录规范、模板解析与检索范围，以及监控、脏状态和版本时间及详情。0.2 在旧 14 列末尾新增“资产类型”（UE 类路径）及“来源槽位内容”，共 16 列；解析脚本应按表头适配。未找到匹配的输入也写入报告，附带 FBX 监控状态；导出前重新评估监控信息。齿轮菜单隐藏信息列不会删减导出字段。

当前暂未提供独立结果文本过滤、逐文件移除、详细导入配置面板或来源未知资产的批量深入加载；可先通过路径范围、折叠分组、列提示及 CSV 审阅。

## 9. 常见问题

### 9.1 为什么“更新所选”没有弹出计划确认？

普通主槽位同源且所选资产/直接依赖均无未保存修改时，会直接执行；这是当前设计。来源不同、存在脏修改或非主槽位内容更新会弹计划风险确认。原生 Auto Reimport 重复更新风险是独立提示，因此“没有计划确认”不保证完全没有其他提示。匹配和全选本身不会自动开始更新。

### 9.2 为什么更新后仍可能暂时不能勾选？

当前版本已修复报告模式永久禁用选择的问题，批次结束且索引合并完成后可以继续勾选。仍不可用时检查是否正在预检/确认、更新、检索、建立索引或合并变化，是否刚改检索配置，或该行是否来源槽位缺失/歧义。没有可选资产的组保持禁用；普通检索结果失效时需要等待刷新。旧二进制可能仍保留旧行为，应使用已编译的 DebugGame 模块重新启动编辑器。

### 9.3 为什么全局全选后是横杠，或没有选中任何行？

全局全选不会替用户选择同一资产的多个 FBX 来源。它跳过冲突项；还有其他可选行被选中时显示横杠，仅冲突项时可能仍显示未选，并提示冲突资产数量。请在对应 FBX 组内全选或逐行明确来源。横杠或勾选状态再次点击都是取消，不是补齐全选。

### 9.4 “版本时间”能证明刚刚更新过吗？

不能。它是导入记录保存的源 FBX 修改时间，同一版本的 FBX 重导入两次可以显示相同时间。它不查询版本控制提交历史，不记录插件操作时刻，不证明数据已经保存；导入后端没有写入时间时显示未知，不用当前源文件或 uasset 的磁盘时间代替。

### 9.5 不自动保存，为什么仍提示会覆盖脏数据？

“不保存”仅意味着插件不主动把资产写回磁盘；重导入仍会修改内存对象，可能覆盖已有未保存编辑。先确认需要保留的数据，必要时手动保存或备份，再决定是否继续覆盖。插件不承诺整批撤销；UE 自动保存、原生 Auto Reimport 和第三方工具也不受本插件的保存策略控制。

### 9.6 已启用 Monitor Content Directories，为什么某行仍是未启用、来源不关联或无法确认？

总开关开启不是充分条件。FBX 必须处在实际活动目录中并通过过滤，资产真实来源还必须关联它。配置刚变化时原生监控有延迟重建，额外运行时目录或第三方过滤规则可能不可见；不确定时不会直接报启用。这个状态也不是原生任务正在运行或已经成功完成的证明。

### 9.7 模板推导目录正确，为什么没有匹配资产？

目录模板只决定查哪里，资产仍需通过源路径或关键词规则。检查类型开关及模板是否适用于当前资产类别、前缀和字段是否正确、目录是否已挂载/被发现、递归设置是否合适，以及是否误用“仅模板目录”排除了其他位置。默认补查模式会取模板目录与原资产目录的并集；零匹配不能推断范围外也没有同源资产。

### 9.8 配置只读、缺少菜单或构建失败怎么办？

配置只读时，当前内存设置仍可检索，但不能保证重开后保留；按团队流程手动签出或处理权限，插件不会替用户签出。菜单缺失时确认插件已启用并使用对应构建配置。链接报插件 DLL 被占用时，先自行处理未保存工作，再关闭加载该模块的编辑器及调试会话后重新构建，不强制结束进程或删除构建目录。

### 9.9 列隐藏或 Tooltip 调整会改变导出数据吗？

隐藏只影响界面，CSV 仍导出完整的 16 个字段；表头说明与单元格详情分层后，详情字段只保留具体记录，不为每行重复通用概念。导出时的选择、脏状态、监控和版本时间反映当前可见状态，不是不可变的历史审计快照；需要留档时应保存当次导出的 CSV。

### 9.10 为什么原来的“来源未知”小组消失了？

旧逻辑把范围内所有未命中的未知来源资产额外追加到了结果，本版已修正。现在仅显示与本次 FBX 有实际匹配证据的资产；其他缺来源资产只在底部计数。名称命中的未知来源候选仍保留在对应 FBX 组，但在修复来源槽位前不能更新。重新启动对应 DebugGame 编辑器并检索后生效，不需要保存或修改原资产。
