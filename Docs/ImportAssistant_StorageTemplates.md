## 1. 核心概念

资产存放模板描述“文件名称中哪些位置代表什么，以及这些字段如何组成资产目录”。插件先从拖入的 FBX 文件名中提取字段，再生成 UE 资产目录，在该范围内执行现有源路径或名称关键词匹配。

目录定位和资产匹配是两个步骤：位于某个角色目录下，不表示该目录中所有资产都应该被当前 FBX 更新。重导入仍需用户主动勾选执行；来源改绑、覆盖脏数据或非主来源槽位内容更新时提示确认，普通主槽位同源且干净时不重复弹计划框。

本功能不读取 FBX 内容来判断模型类型，不创建目录，不移动或重命名任何资产。

## 2. 最小动画示例

输入：`AN_Male_Run_Loop.fbx`

在窗口左侧“资产存放模板”中：

1. 勾选“启用资产存放模板”。
2. 检索策略保留“模板目录优先，补查原资产目录”。
3. 确保“资产目录”至少保留一个合法已挂载范围，用于补查或模板不适用时回退；这是独立于模板数组的设置。
4. 在“存放模板”数组中添加一项，按下表填写。

| 配置项 | 值 |
| --- | --- |
| 启用 | 是 |
| 模板名称 | 角色动画 |
| 资产类别 | 动画序列 |
| 规范说明 | 动画按角色名归档到角色目录下的 Animations 文件夹 |
| 名称前缀 | `AN_` |
| 分隔符 | `_` |
| 目录模板 | `/Game/Character/{Name}/Animations` |

“字段定义”数组：

| 词段位置 | 变量名 | 含义说明 |
| --- | --- | --- |
| 1 | `Name` | 角色名 |
| 2 | `Action` | 动作名 |
| 3 | `Variant` | 动作变体 |

解析步骤：

```text
AN_Male_Run_Loop.fbx
→ 去掉扩展名：AN_Male_Run_Loop
→ 移除模板前缀：Male_Run_Loop
→ 按 _ 分段：[Male] [Run] [Loop]
→ Name=Male，Action=Run，Variant=Loop
→ /Game/Character/Male/Animations
```

`Female` 会生成 `/Game/Character/Female/Animations`，不做 `Male` 子字符串匹配。这里不需要为每个角色单独写一条规则。

以上目录仅为示例，插件不会自动添加或启用该模板。请根据项目真实目录结构配置；当前工程旧设置保持不变。

## 3. 规范编写约定

### 3.1 字段位置

- 词段位置从 **1** 开始，按移除模板前缀后的名称计数。
- 分隔符按字面解释，不支持正则；可使用多字符分隔符。
- 保留空词段。`Male__Run` 的第 2 段为空，第 3 段才是 `Run`，不能将其自动提前。
- 允许文件名包含额外词段；模板只读取声明的位置。
- 只有被目录模板引用的字段必须存在且非空。未用于目录的说明字段可以缺失，预览会显示缺失或为空。

### 3.2 前缀与大小写

- 模板前缀非空时，文件名必须具有此前缀才适用此模板。
- 前缀比较忽略大小写，提取的变量值保留原始大小写。
- 模板分段不使用“关键词匹配”中的忽略前后缀设置，避免两套设置互相改变位置。
- 变量名区分大小写：`{Name}` 与 `{name}` 不相同。
- 变量名必须以字母或下划线开头，后续只允许字母、数字和下划线；同一模板内变量名不能重复。

### 3.3 目录模板

- 必须使用 UE 包路径，如 `/Game/Character/{Name}/Animations`，不是 `G:\Project\Content` 磁盘路径。
- 支持已经挂载的插件内容根；根目录本身必须写死，不能使用 `/{Root}/...`。
- 可重复引用字段，如 `/Game/Character/{Name}/{Name}_Animations`。
- 不支持条件表达式、脚本、正则捕获或嵌套变量。
- 禁止 `..` 越级路径、空目录段、反斜线，以及引擎不允许的包路径字符。
- 被代入的字段只能表示一个合法目录名称，不能通过字段插入 `/` 或 `\` 来改变目录层级。
- 固定目录模板也可使用，例如 `/Game/Common/Animations`，但应配置清晰的前缀以免适用范围过宽。

### 3.4 多模板

一份 FBX 可以适用多份模板，插件合并所有推导目录，不采用“第一条命中覆盖后续规则”。

开启递归时，父目录已覆盖的子目录从查询范围中去除；关闭递归时保留父目录和子目录，避免漏掉本层资产。合并仅影响查询范围，解析预览仍保留各个命中模板的依据。

未启用的模板不校验、不参与解析。开启模板功能后，所有启用模板的配置都要合法，包括模型类别；每个启用资产类别只使用同类别模板。编辑中的不完整模板可以先取消该项“启用”。

## 4. 模型模板示例

### 骨骼模型

```text
模板名称：角色骨骼模型
资产类别：骨骼模型
名称前缀：SK_
分隔符：_
字段：第 1 段 → Name（角色名）
目录模板：/Game/Character/{Name}/Meshes

SK_Male.fbx → /Game/Character/Male/Meshes
```

### 静态模型

```text
模板名称：场景静态模型
资产类别：静态模型
名称前缀：SM_
分隔符：_
字段：第 1 段 → Category（分类），第 2 段 → Name（模型名）
目录模板：/Game/Environment/{Category}/{Name}

SM_Props_Chair.fbx → /Game/Environment/Props/Chair
```

以上三类模板已正式接入；需在“检索范围 → 资产类型”勾选模型类别。旧类别枚举值不变，0.2 仅去掉预留标签，旧模板可直接使用。开启模板会逐 FBX、逐启用类别生成范围；FBX 名称可适用于多个类别，不会把某类别目标目录当作其他类别的有效范围。

## 5. 检索策略与完整性

### 默认：模板目录优先，补查原资产目录

每份 FBX 在每个资产类别下的有效范围：

```text
该 FBX 的推导目录 ∪ 设置中的原资产目录
```

即使规范目录已经找到资产，也继续保留原目录补查结果。结果组内优先展示模板目录内资产，其他命中行在“匹配依据”列标记“模板目录外候选”，仍可按正常条件勾选更新。

此处“优先”指结果排序和规范提示；检索一次完成，不会先发布半份可执行结果再延迟补查。如果原资产目录仍配置为 `/Game`，首次索引仍需覆盖该范围，不能声称模板消除了全局索引成本。

### 可选：仅模板目录

只有成功推导出的目录参与该 FBX 的查询。分组和总状态均提示“未检查模板目录外资产”，不能将其结果理解为全工程同源资产清单。

当前类别没有模板适用时，单独回退原资产目录，并显示前缀不匹配、字段缺失等原因。因此两种模式都要求保留至少一个合法的原资产目录作为回退范围。

### 逐文件及逐类别隔离

批量输入可能将 Male 和 Female 的目录共同加入元数据索引，但每份 FBX 的候选匹配只允许使用自己的有效范围。只有显式配置的原范围包含其他角色目录时，补查才会覆盖它们。静态模型模板命中的目录不会扩展动画/骨骼模型范围；即使索引目录并集覆盖了这些位置，候选和未知来源诊断仍按各自类型范围过滤。未知来源仅因位于目录内不会进入结果，必须实际命中关键词；没有来源槽位仍禁止更新。

### 配置错误与零匹配

- 未定义变量、重复变量、非法目录模板等属于配置错误，阻止本轮检索并指出模板序号及原因。
- 某个文件缺少需要的词段，属于该文件无法使用该模板；其他模板仍可尝试，无可用模板则回退原范围。
- 目标路径的内容根合法、但 Asset Registry 尚未发现该目录时，分组显示“规则目标目录不存在或尚未被发现”，不自动创建目录。
- 修改文件夹或挂载状态后可点击检索刷新，重新确认目录状态。
- 模板目录外且不在原配置范围内的资产不属于本轮完整性承诺。

## 6. 窗口、审阅和报告

### 配置后的操作

1. 编辑完成后设置由 UE Config 自动保存到插件，左侧若显示配置写入错误先处理共享文件权限；插件不主动签出。
2. 添加或拖入 FBX，等待范围验证、索引和完整匹配结束。已有文件时修改模板会使结果失效，点击“检索 / 刷新”重新应用；不依据旧结果执行。
3. 在每个 FBX 的分组说明中核对字段解析、推导目录和实际补查范围；模板不适用、目录未发现或零匹配都不能直接解释为全工程没有同源资产。
4. 审阅源路径/关键词匹配证据后逐项、组内或全局选择。全局全选会跳过多 FBX 来源冲突项；组内全选视为选择该组 FBX，会取消其他组同资产的互斥来源。折叠组也参与操作。
5. 点击“更新所选…”触发准确预检，来源改绑、资产/直接依赖脏修改或非主来源内容更新会弹风险计划；原生自动重导入风险提示独立存在。确认后允许覆盖脏编辑，仅更新内存，保存交给用户。
6. 结束后可继续勾选下一批，无需每批强制检索；再次执行重新读取所选资产当前来源与脏状态。修改模板或范围仍必须重新检索。

### 分组与列提示

FBX 分组标题下显示：模板名称、字段解析、推导目录和检索策略。悬停该说明可查看规范说明、字段位置、失败原因与实际范围；标题本身的 Tooltip 仍为 FBX 完整文件路径。

“匹配依据”列标题的 Tooltip 解释字段含义，资产单元格保留具体关键词/源路径证据，并对适用模板的资产附加存放规范信息。目录外标记是独立字段，不会在勾选、取消选择或重导入状态更新时丢失。

CSV 的“目录规范”和“模板解析与检索范围”字段保留逐文件范围说明，零匹配也带解析信息，便于区分没有命中与模板限制。当前完整报告共 16 列，在旧 14 列末尾增加资产类路径和来源槽位内容；齿轮隐藏任何信息列不删减导出字段。版本时间指已导入 FBX 的记录时间，不是模板解析或重导入操作时刻；报告是当前可见状态，不是历史审计数据库。

## 7. 配置与性能

模板、字段数组、启用开关和检索策略使用 `UPROPERTY(Config)`，随现有设置保存到插件 `Config/ImportAssistant.ini`。旧配置没有这些字段时默认关闭模板功能，不改变原来的查询行为。

解析在查询启动时完成，每份文件对每份适用模板分段一次；后台匹配只接收不含 UObject 的范围和值快照。查询范围未变化时复用原索引，改动说明文本不会重建磁盘索引，但需要刷新预览。

模板解析和普通检索不加载资产对象、不向在线服务发送请求、不执行用户脚本，也不自动签出配置或资产；源路径若在网络盘，候选文件存在性验证仍可能访问网络文件系统。随后用户点击更新时的风险预检会加载全部本次所选资产及相关依赖，不能把模板解析的成本说明套用到更新执行。

## 8. 配置排查

| 现象 | 检查内容 |
| --- | --- |
| Male 被解析为其他词段 | 位置从移除模板前缀后按 1 开始计数；空词段不被丢弃；不要混淆模板前缀与关键词忽略前缀 |
| 输出仍含 `{Name}` 或提示变量错误 | 变量区分大小写，目录引用的变量必须有定义，检查字段重名与词段位置 |
| 动画模板不起作用 | 检查全局开关、单项启用、动画类别、名称前缀及分隔符；模型类别只预留保存，不参与动画窗口 |
| 已有规范目录但仍看到其他目录候选 | 默认“模板优先”是模板目录与原目录并集，不是命中模板后停止；若原范围是 `/Game`，仍会覆盖该原范围 |
| 规范目录没有候选，但回退后有结果 | 目录只是定位层，核对实际动画位置、源路径/关键词规则和发现状态，不自动移动旧资产 |
| 只看到某角色目录，担心漏检 | 检查是否使用“仅模板目录”；此模式明确不保证模板外完整性，必要时改回默认补查并扩展合法原范围 |
| 修改规范说明后仍显示旧预览 | 修改说明不执行磁盘目录重排；重新检索以更新当前任务的解析与范围显示 |
