## 1. 背景与目标

动画师更新 FBX 后，一份源文件可能对应分布在不同目录中的多个 AnimSequence。这些资产可能具有不同名称、Skeleton、帧范围或采样设置，人工逐个查找和重导入容易遗漏。

插件提供一个独立编辑器窗口，允许用户拖入一个或多个 FBX，在指定的 UE 资产目录内按源文件路径或名称关键词检索动画，按 FBX 分组展示候选资产，并由用户勾选更新。

本插件解决的是“找到所有需要检查的同源资产，并明确说明哪些更新、哪些没有更新”，不是重新实现 FBX 导入器，也不以完全消除重导入耗时为目标。

### 1.1 核心目标

1. 支持同一 FBX 对应多个已有 AnimSequence，避免只匹配一个资产。
2. 支持多个资产目录及递归搜索，不局限于当前 Content Browser 文件夹。
3. 支持源路径精确匹配、用户配置的路径映射匹配、资产名称关键词匹配。
4. 搜索阶段避免加载动画对象，保持窗口可响应，并明确展示检索是否完成。
5. 保留每个资产自己的导入配置，逐项更新并报告结果，资产保存由用户自行完成。
6. 让未勾选、匹配歧义、来源未知、更新失败和待用户保存的资产可见。
7. 为后续无编辑器窗口的 Commandlet 更新保留共用业务逻辑。

### 1.2 第一版不包含

- 自行解析 FBX 并生成动画轨道。
- 自动推断缺失来源的动画与 FBX 之间的真实关系。
- 自动重新生成重定向动画、Montage、BlendSpace 或其他派生产物。
- 自动修改所有资产的导入配置，或强制切换 Legacy FBX / Interchange 导入后端。
- 绕过 UE 直接编辑 `.uasset` 二进制。
- 承诺整批操作能通过一次 Undo 完整回滚。
- 自动提交版本控制变更。
- 第一版即提供外部独立 GUI、数据库、跨会话持久化索引或泛化导入框架。

## 2. 现有方案调研与选型

### 2.1 调研结论

UE 已经具有成熟的源文件关联查询和重导入能力，市场上也存在相关商业插件；但 2026-11-07 调研的公开资料没有证实某个现成产品完整覆盖“拖入任意 FBX → 在指定范围反查全部已有同源动画 → 保留逐资产配置 → 用户勾选更新”的工作流。

原始调研核查了产品说明和本地源码，未购买、安装或实测商业插件；2026-11-10 的文档整理没有重新联网核验产品现状。以下能力描述不等于对产品可靠性、性能或项目兼容性的验收结论。

| 方案 | 公开说明或源码已确认的能力 | 与本需求的差距 |
| --- | --- | --- |
| UE 原生 Auto Reimport | 监控源文件目录，查找关联资产，并在源文件变化后重导入 | 不提供本需求的拖入文件、灵活匹配、逐项审阅工作流 |
| Sentinel Importer – Batch Import & Reimport | 批量导入/重导入 FBX 动画，共享和逐文件配置，Smart Sync，手动决定更新 | 未确认是否完整反查项目中一个源文件对应的多个已有动画，以及是否保留各自截帧配置 |
| Smart Auto Reimport | 用户先选定资产开启监控，源文件变化后调用原生重导入 | 仍要求用户先选全资产，可能继续漏选同源动画 |
| Source Link | 从 Asset Registry 检查和修复源文件路径，提供 Commandlet 和歧义报告 | 主要修复来源路径，不负责本需求的动画内容更新与选择窗口 |

### 2.2 推荐选择

采用轻量 C++ Editor 插件：自研发现、匹配、预览和执行协调，复用 Asset Registry、资产导入数据及原生重导入接口，不修改引擎。

如果优先考虑购买，先用 Sentinel Importer 验证以下场景：同一 FBX 对应三个不同目录、不同帧范围的 AnimSequence，其中两个未加载；工具必须找齐且分别沿用原有配置重导入。未通过该验证，不把它视为完整替代方案。

## 3. 用户工作流与窗口设计

### 3.1 操作流程

```text
设置资产搜索范围与匹配规则
    ↓
拖入一个或多个 FBX
    ↓
等待资产发现，建立或更新元数据索引
    ↓
后台匹配完成并校验版本，一次发布本次结果（等待期间仅显示状态）
    ↓
用户审阅并勾选资产，处理来源冲突与路径改绑
    ↓
加载本次所选资产准确预检；来源改绑/脏修改/非主来源内容更新时确认，原生监控风险独立提示
    ↓
逐项重导入，保留待保存状态
    ↓
保留成功、失败、未执行及未选择结果，恢复选择；再次执行重新定稿计划，资产由用户保存
```

### 3.2 路径概念

| 路径类型 | 示例 | 用途 |
| --- | --- | --- |
| 资产搜索目录 | `/Game/Characters/Hero` | 限制 UE 资产范围，可配置多个目录及递归 |
| 实际 FBX 路径 | `D:/Art/Characters/Hero/Run.fbx` | 本次用户拖入的文件 |
| 资产记录的源路径 | 包相对路径或历史绝对路径 | 确认资产原来的导入来源 |
| 源路径映射 | `D:/OldArt/` → `E:/Art/` | 处理源目录迁移及成员工作区差异 |

支持用户明确选择的项目内容和已挂载插件内容目录。默认搜索范围不代表整个工程，未挂载内容不属于完整性承诺范围。

### 3.3 窗口区域

1. **配置区**：搜索目录、递归选项、匹配方式、关键词规则和源路径映射。
2. **文件区**：资源管理器 FBX 拖入、“添加 FBX…”和“清空本次文件”；输入以结果区分组表示，当前没有独立的逐文件移除入口。清空只改本次任务，不删除磁盘文件或资产。
3. **结果区**：按 FBX 添加顺序分组的虚拟化树形列表，组标题为文件名，Tooltip 为完整文件路径；支持折叠、勾选和定位资产，零匹配文件保留小组。文本过滤为后续增强。
4. **状态区**：底部统一展示资产发现、索引、查询、未知来源数量及操作进度；仅在此保留“导出报告”按钮。
5. **执行区**：结果区右上独立一排右对齐，仅放置“选择明确同源项”和合并的“更新所选… / 停止更新”按钮，原“取消选择”改由三态勾选框承担；停止请求后显示“正在停止…”并禁用，等待当前资产完成。文件及检索操作仍在顶部第一排，窄窗口可换行。

6. **列表工具栏**：表头上方独立一行，左侧显示文件数量与说明，右侧使用原生设置齿轮弹出列勾选菜单；与右上选择/更新操作栏分离。

移除窗口中的输入记录仅改变本次任务，不删除磁盘文件或 UE 资产。

### 3.4 当前结果字段

| 固定/可选 | 列 | 数据与展示范围 |
| --- | --- | --- |
| 固定 | 选择框 | 表头全局三态、资产行单选；组标题另外提供组内三态 |
| 固定 | 资产 | 三类目标名称，点击定位，Tooltip 含对象路径及适用的 Skeleton 标识 |
| 可选 | 类型 | 官方 AssetDefinition 名称与类型色，单元格列出 UE 类与文件格式 |
| 可选 | 资产路径 | UE 资产包路径，不是源文件磁盘路径 |
| 可选 | 原来源 | 检索时来源记录快照，报告保留；执行另读当前实际来源 |
| 可选 | 匹配依据 | 精确路径、映射或关键词，可以同时命中，单元格保留证据 |
| 可选 | 自动重导入 | 原生目录/过滤/真实来源关联的当前可见状态，非任务运行状态 |
| 可选 | 是否脏数据 | 目标及直接依赖包的未保存修改，Tooltip 列角色与具体对象 |
| 可选 | 版本时间 | 上次导入记录的源文件修改时间（UTC），非导入或保存操作时刻 |
| 可选 | 状态 / 结果 | 选择状态或最近一次执行结果，含失败及未执行原因 |

八个信息列由齿轮统一控制，不为每个分组单独保存列配置。表头解释字段含义和边界，单元格只展示对应资产的实际详情。Skeleton 目前不是独立列；磁盘只读/版本控制状态也不是独立列或内存更新的阻止条件。帧范围、Take、采样等没有专用预览列，执行时由既有原生导入数据决定，不为填充列表批量加载对象。

### 3.4.1 信息列显隐（已实现）

类型、资产路径、原来源、匹配依据、自动重导入、是否脏数据、版本时间、状态 / 结果共八列由齿轮菜单统一控制所有分组，选择框与资产名称始终可见。默认全部显示，支持恢复默认。菜单勾选后保持打开，勾选状态动态绑定表头。

通过 `SHeaderRow::SetShowGeneratedColumn` 切换实际生成列；固定列设置 `ShouldGenerateWidget(true)` 防止隐藏，表头列变更通知 Slate 重新排列资产单元格。隐藏列不占空位，剩余填充列重分配宽度；不替换结果、不重建分组、不触发检索或取消任务，因此保留勾选、展开和结果状态。

隐藏列 ID 使用现有设置对象的 `UPROPERTY(Config) TArray<FName> HiddenResultColumns` 保存到插件配置，启动应用。载入前清空数组，兼容空配置和没有列字段的旧配置；未在隐藏列表中的新列默认可见，未知 ID 不影响固定列。CSV 始终按完整字段导出，不依赖可见列。配置失败沿用已有提示，不签出文件。

引入列显隐时新增 `ImportAssistant.Editor.ColumnVisibilityAndToolbar` 与 `ImportAssistant.Settings.ColumnVisibilityConfig` 两项回归，覆盖菜单动作、生成列、布局、固定列、默认恢复、选择/展开与 Config 往返；当时全量为 32 项。最近一次剩余完整集合为 51 项，实际窗口截图视觉仍待验收。

### 3.4.2 全局与分组三态勾选（2026-11-09 已实现）

表头选择列替换为全局三态复选框，各分组标题前增加同样控件。未选点击全选；部分已选（横杠）或全部已选点击取消，状态由当前实际选择推导，初次检索默认未选。范围包含折叠组，组内操作不展开或折叠小组，不可选行不计入统计；无可选项时禁用，过期结果、匹配未完成及更新中禁止修改。

全局全选跳过多 FBX 来源冲突项并提示，不按遍历顺序替用户选来源；组内全选明确选择该 FBX，取消同资产在其他组的互斥来源。保留关键词/路径映射候选的主动批量选择能力和既有更新确认。右上移除“取消选择”按钮，保留明确同源项及更新/停止入口。

`FResultNode` 记录每组可选/已选计数；窗口记录全局计数及 FBX→组、资产对象路径→已选行索引。单项和互斥变更增量维护计数，控件读取三态为 O(1)，批量操作按本范围处理；分组重建时重算缓存并保留展开状态。不会在可见复选框求值时遍历全列表，也不因选择重建索引或加载资产。

该功能当时新增三项 `ImportAssistant.Editor.Selection.*` 回归，覆盖三态范围、折叠、冲突、禁用及缓存；当时全量为 35 项。后续新增报告恢复选择测试，目前剩余 51 项的记录以第 10 节及使用说明为准。实际窗口截图和端到端鼠标/键盘交互仍待人工验收。

### 3.4.3 脏状态、版本时间及报告后继续选择（2026-11-09）

脏状态按动画及关联 Skeleton 所在包的 `IsDirty()` 判断，显示具体脏资产及 Tooltip 路径，加入齿轮和 CSV。不批量加载列表资产，通过对象/包及元数据查询缓存；事件与索引变化触发节流刷新，执行前加载所选对象准确复核。已确认的脏资产允许重导入覆盖，不再预先跳过，仍不自动保存。

版本时间取 `FAssetImportInfo::FSourceFile::Timestamp`，含义为上次导入记录的源文件修改时间，而非操作时间或保存时间。索引快照携带每槽位 UTC 时间，按本行来源槽位显示；表头 Tooltip 说明时间语义，单元格 Tooltip 仅列全部来源记录和时间及缺失情况。没有时间显示未知，不查当前磁盘文件替代。索引变化及更新结束刷新当前内存/注册表元数据，原报告来源和结果不被覆盖。

`CanSelectResults()` 与 `CanExecute()` 分离；报告模式不再因 `bShowReport` 或上批修订号永久禁用复选框，索引就绪后允许全局、组内及单项选择。再次执行通过当前所选对象的实际来源与脏状态创建全新计划，不使用上批来源 JSON 作为执行依据；普通检索模式仍拒绝失效结果。预检、确认、更新及未完成检索期间继续禁用，选择不改变既有执行结果。

该轮另增版本元数据、版本 UI 刷新、报告恢复选择、连续批次预检四项，彼时总计 43 项通过；随后表头备注回归使当时集合达到 44 项，本轮三类型扩展后为 53 项。初次链接的 DLL 占用问题在编辑器与调试会话正常退出后解除，未强制结束进程。模块编译链接成功；真实 FBX 与窗口人工验收边界见使用说明。

### 3.4.4 字段备注与数据详情分层（2026-11-09）

信息列定义集中保存 ID、标题、字段备注和原相对宽度，构造时通过 `SHeaderRow::FColumn::DefaultTooltip` 绑定静态表头说明；齿轮菜单复用同一备注，避免说明与显隐项不一致。资产名固定列表头也补充定位含义，选择框原三态操作提示不变。动态值仍从既有缓存读取，不新增悬停查询或资产加载。

版本时间的通用含义、读取来源与保存边界从每条数据的 Tooltip 迁至表头；脏状态和自动重导入的概念、能力边界同样迁移，单元格只保留具体资产/来源/监控设置与判断结果。类型格式、完整路径、命中关键词、失败原因等实际详情继续保留。CSV 字段结构不变，详情文本不重复通用解释。

新增 `ImportAssistant.Editor.ColumnHeaderRemarks` 验证实际 Slate 表头 Tooltip、显隐恢复、顺序与列宽及具体数据提示；调整既有元数据与状态测试，当时完整 44 项回归通过，模块构建成功。人工窗口视觉验收仍未进行。

### 3.4.5 三类 FBX 资产扩展（0.2.0，2026-11-10）

类型配置采用三个 Config 布尔开关，默认 AnimSequence/StaticMesh/SkeletalMesh 全开，禁止空类型集；旧配置无字段时默认三类。索引按启用类过滤，所有三类内存/注册表来源和对象事件纳入增量；UI 入口为“FBX 资产导入助手”，原 Tab ID 不变，沿用分组、颜色、列显隐、三态及条件确认。

## 4. 匹配规则与源路径处理

### 4.1 精确路径匹配

读取每个来源记录，结合资产包目录及 UE 来源解析规则形成路径候选，再与规范化后的拖入路径匹配。不能只处理 `SourceFiles[0]`，索引应保留全部来源记录和对应 `SourceFileIndex`。

比较键应统一目录分隔符、相对段及末尾分隔符；通常的 Windows 不区分大小写工作区可使用忽略大小写的比较键，同时保留原始显示路径。启用了大小写敏感目录的工作区需要另行验证，不能静默合并真实不同文件。

映射盘、UNC 路径、符号链接和不同机器盘符不自动视为相同位置；需要显式映射，或后续增加经过验证的文件身份解析策略。

### 4.2 路径映射匹配

- 映射规则按完整目录边界匹配，不使用任意子串替换。
- 重叠规则优先使用更长的源目录前缀；等价优先级仍有多解时报告歧义。
- 同时显示原始路径、映射规则和映射后的路径。
- 路径映射只影响检索结果，不在扫描时写回资产。
- 执行时单独确认是否把资产来源改为本次拖入的实际文件。

### 4.3 关键词匹配

第一版匹配对象明确为 `AnimSequence` 资产名称，不默认搜索整个资产路径或任意元数据。

支持去掉 FBX 扩展名、按配置数组顺序移除第一个匹配的前后缀，再按下划线、短横线、空格、点提取关键词。提供“全部关键词”和“任意关键词”，使用名称包含各关键词的比较方式，没有第三个独立“名称包含”开关。关键词为空时不应产生全选结果。

同名不同目录、类似名称和不同角色共享动作名都可能产生误匹配，所以结果必须展示匹配原因，且不能自动当成同源确认。

### 4.4 组合匹配和去重

启用多种规则时取结果并集，按“FBX 标识 + 资产标识”去重，同时保留全部命中依据。不能默认取交集，否则源路径失效的动画可能被重新过滤掉。

另按资产标识检查跨 FBX 冲突。一个资产只进入一次执行计划，不能按列表顺序被多个源文件反复覆盖。

### 4.5 相对路径和失效来源的处理

本地 `UAssetImportData::ResolveImportFilename` 涉及包目录、数据源目录及文件存在性检查，不能简单使用项目根目录拼接所有来源，也不能在后台对大量网络路径无差别检查存在性。

索引阶段保留原始来源、包路径和纯字符串计算的候选键；引擎设置与挂载信息在适合的线程采集成快照。仅对需要确认的候选做最终来源解析，并对相同来源复用结果。

如果解析依赖失效旧目录而无法确认，应标记为路径映射候选、歧义或未知来源，不伪装成精确命中。最终执行所用的 FBX 必须可访问，并与用户确认的来源一致。

来源 MD5 可以用于辅助诊断或内容变化提示，但不能作为同源匹配的必要条件：动画更新后，新 FBX 的内容本来就可能与旧导入哈希不同。

## 6. 索引与检索性能

### 6.1 基于注册表元数据，不遍历加载动画

三类资产的 `GetAssetRegistryTags()` 将导入来源写入注册表 Tag，可从 `FAssetData` 提取 `FAssetImportInfo`。检索阶段禁止为了读取来源调用 `GetAsset()`、`LoadObject()` 或 `TryLoad()`。

通过 `FARFilter` 限定启用的三类类型、搜索目录和递归范围。资产范围应先过滤，再解析 JSON、规范化路径和执行匹配，避免重复解析其他类型资产。

### 6.2 会话内索引

当前维护：

- 资产对象路径到只读记录的映射。
- 规范化来源候选键到多个资产记录的倒排映射，命中后确认具体来源槽位。
- 可复用的搜索快照及未知来源数组；关键词匹配扫描范围内记录的资产名称，当前没有独立的名称倒排索引。

首次配置范围时请求 UE 异步资产发现并建立范围内元数据索引，之后响应变化事件增量更新；范围改变或显式重建索引会重新构建。一次拖入多个 FBX 时复用同一索引。`SearchAllAssets(false)` 可能推进 UE 的全局发现，限定范围减少插件查询/解析量，但不表示引擎仅扫描这些目录。

设资产数量为 N、输入 FBX 数量为 F、结果数量为 K：无映射且未启用关键词时，直接源路径候选查找主要是哈希访问与命中合并，但还包含范围/槽位校验及结果整理，不承诺总耗时严格 O(F + K)。开启路径映射会遍历来源键；关键词对各 FBX 扫描候选名称。匹配阶段还可能按缓存验证候选路径是否存在，网络盘访问和排序/去重也可能有成本，必须分别测量。

第一版不增加磁盘索引数据库；先利用 UE 自身注册表能力和会话内缓存。仅在测量证明必要后，再考虑持久化与失效机制。

### 6.3 内置源文件缓存的使用边界

UE 的 `FAssetSourceFilenameCache::GetAssetsPertainingToFile()` 已提供源文件反查能力，原生 Auto Reimport 使用它查找关联资产。

该缓存可作为实现参考和精确匹配的验证依据，但其首次初始化、任务等待、全工程范围及路径语义不能直接替代插件的范围控制、关键词检索、映射和完整性状态。也不能因为缓存内部有任务队列，就假定公开查询可以任意从工作线程调用。

当前插件维护一份限定范围的动画索引，不通过逐文件调用原生源缓存再重复维护一套全工程缓存。自动重导入状态评估参考原生源关联路径语义，但不把插件映射或关键词当作原生关联证据。

### 6.4 避免主线程峰值

- 后台基线按 `FARFilter` 一次取出范围内磁盘记录后解析；不把单次注册表取数描述为可任意中断。内存覆盖和增量合并在 Tick 中按时间预算处理，但单次内存枚举或标签生成仍可能有峰值。
- 工作线程处理不可变元数据快照，合并时进行版本校验。
- 后台匹配完成并经版本校验后一次发布结果；列表虚拟化只生成可见控件，不采用可执行的分批结果发布。
- 对同一路径复用规范化和验证结果，避免重复网络盘访问。
- 未匹配文件不触发全工程对象加载。
- 用户更改配置后丢弃旧查询结果，不让过期结果覆盖新结果。

异步工作仍可能因注册表锁、数据复制或主线程收尾产生峰值，是否达到响应性目标必须通过实测判断。

## 7. 线程模型和完整性保证

### 7.1 线程职责

| 工作 | 执行位置与限制 |
| --- | --- |
| 已保存资产注册表查询 | 在核实当前版本查询路径及扩展回调线程要求后，后台执行仅磁盘资产查询 |
| JSON 解析、字符串处理、索引构建和匹配 | 后台，仅访问任务拥有的数据或不可变快照 |
| 内存资产和未保存来源采集 | 主线程；不在普通工作线程枚举 UObject |
| 结果发布与 UI 更新 | 主线程一次接收有效的完整匹配结果，重建分组；列表按可见行虚拟化，不保证大结果合并无峰值 |
| 对象加载、属性修改和重导入协调 | 遵循引擎主线程要求，不自行把对象操作包装为并行任务 |

默认 `GetAssets()` 可能枚举内存对象。本地源码对该路径有线程限制，后台基线查询应使用 `bIncludeOnlyOnDiskAssets = true`；这只提供磁盘状态，不能替代内存覆盖。

主线程可使用适当的内存资产查询采集最新状态。底层一次查询或一个资产的 Tag 生成不一定可中断，不能仅靠外部 Tick 预算保证严格耗时上限；实际出现峰值时应缩小批次或调整采集方式。

### 7.2 基线与增量合并流程

1. 注册资产新增、删除、改名、更新及导入来源变化事件，再启动初始快照。
2. 确认目标模块已就绪、所选内容根已挂载、所选范围已发起发现。
3. 发现未结束时展示等待/索引状态；旧结果不可执行，不发布新的可执行部分清单。
4. 获取磁盘元数据基线，后台建立索引。
5. 主线程采集内存中新建、未保存或来源已变化的资产，覆盖对应磁盘记录。
6. 合并建立基线期间收到的事件；对变更资产重新取最新记录，避免旧快照覆盖新状态。
7. 发现结束且当前增量合并后，后台匹配快照，回到主线程再次校验修订号，完整发布一次；过期/取消任务丢弃，之后继续响应增量事件。
8. 执行前复核选中资产的存在性、来源及修订状态；发生相关变化时刷新计划并要求必要的重新确认。

需关注 `OnFilesLoaded`、资产增删改事件以及 `UAssetImportData::OnImportDataChanged` 等来源变化。实际事件选型和批量形式以本地 UE 5.8.1 接口为准。

编辑器界面不在 Tick 中同步等待全工程扫描。`OnFilesLoaded` 可能已经发生，不能只注册事件而不检查当前状态；初始扫描结束后新挂载的目录仍需重新确认范围是否已发现。

Commandlet 可以在初始化和显式扫描后等待必要工作结束，但不能在插件类尚未加载的早期阶段把 `WaitForCompletion()` 返回当成全部资产已发现的证明。

### 7.3 状态模型

```text
等待发现 → 建立索引 → 合并变化 → 就绪
                  ↑               ↓
                  └── 范围或来源变化 ──┘
```

查询记录启动时的索引修订号，并结合设置脏标记、取消令牌和索引就绪状态校验；设置变化、取消或窗口关闭后，不发布旧任务结果。普通模式索引变化触发重新匹配；报告模式保留已有结果，选择须等索引合并就绪，更新时重新预检当前对象。任务退出、事件解绑和对象生命周期统一管理，不让后台回调访问已关闭窗口。

### 7.4 完整性的定义

“完整”仅指：当前配置的、已挂载并已完成发现的范围内，所有可发现的已启用三类资产都已纳入处理；可靠来源的同源资产不因线程调度遗漏；未知来源和解析失败也被计数并报告。

它不表示整个工程所有磁盘文件都已扫描，也不表示没有来源信息的资产被正确恢复了关联。

建议显示：扫描范围、已启用类型资产总数、可解析来源数量、未知来源诊断数量、当前候选数量和完成状态。取消、部分失败、未挂载范围或未完成发现时，不显示“完整检索完成”。

### 7.5 未知来源的补充检查

缺少可用来源记录不构成匹配依据。没有命中任何 FBX 的未知来源资产只参与范围诊断，以 `UnmatchedUnknownCount` 去重计数，不创建结果行或独立小组；按实际类别和目录范围过滤。关键词命中的未知来源候选归入对应 FBX 组，保留实际命中词；缺少来源槽位时不可执行更新。用户主动触发的深入检查仍是后续可选增强，当前没有该入口，不会在每次拖入时自动批量加载这些资产。

对象中同样没有来源信息时，只能保留未知状态或由用户确认关键词关联。不能自动修复来源后再宣称原本就精确匹配。

## 8. 重导入、保存与错误处理

### 8.1 执行前形成明确计划

每个执行项必须明确：哪个已有资产、使用哪个实际 FBX、对应哪个来源槽位、是否改变来源路径、如何处理该资产已有的未保存修改。

路径不一致时区分“沿用旧来源”与“使用拖入文件更新”。本工具的默认目标应是使用用户确认的拖入文件，而不是无提示地读取资产旧路径下的文件。

点击更新后加载所选资产、完成相关编译，按实际导入后端解析当前来源并构建脏状态快照；来源改绑、所选资产/直接依赖存在未保存修改或非主来源槽位内容更新时弹出风险确认。普通主槽位同源且干净直接执行。弹窗列出有界风险预览，共享骨骼去重，完整计划复制到剪贴板。独立 Auto Reimport 提示仍按其原风险判断执行。

用户确认后允许覆盖已经脏的目标资产/直接依赖，不清除脏标记、不重载磁盘版本、不自动保存。跟踪计划涉及包的修改/属性/事务/脏状态事件，复核实际来源、适用的关联骨骼、直接依赖、修订和脏状态；确认后或项间新增修改需重新确认。本批成功导入自身产生的共享包修订可接受，实际导入失败停止后续任务。没有事件报告的直接内存写入无法可靠识别，执行期间仍禁止并行编辑。

再次执行报告中的资产时重新预检当前来源，不沿用上批已失效的 JSON；普通检索执行仍检查来源快照一致性。元数据/必要对象无法准确取得时不静默执行，先报告预检错误。成功结果仍是“已更新，未保存”，保存由用户决定。

### 8.2 沿用资产导入配置

针对已有三类对象调用 `FReimportManager` 和对应后端，沿用每个资产原有导入数据/管线。动画继续使用截帧/采样等设置，模型不被改成动画流程；不主动统一材质槽、碰撞、LOD 或骨骼设置，但后端可能改变这些数据，必须真实样本验收，不承诺无条件保留。

同一 FBX 下不同资产分别使用自己的设置。多 Take 或源节点标识发生变化时，应报告不兼容或需要人工确认，不能自动猜测新的对应片段。

Legacy FBX 与 Interchange 都需要测试；不能假定两者配置结构、路径更新方式、完成回调和错误结果相同。第一版不自动转换后端；确需转换的场景另行评估和确认。

### 8.3 队列执行

第一版一次执行一个资产，保留逐项进度。Legacy FBX 导入路径包含共享导入器，不使用 `ParallelFor` 并行重导入多个动画。

`FReimportManager::ReimportAsync()` 在 Legacy 路径仍可能同步调用工厂。Interchange 的异步流程也包含主线程对象操作，不能承诺单个重导入完全不卡顿。

当前停止操作只请求取消后续项，等待已启动项完成后停止，不强行中断单项 Legacy 或 Interchange 重导入。已完成内存更新不回滚；后续若引入后端级中断，必须另行验证安全性，当前没有该能力。

### 8.4 来源路径写入和失败状态

- 检索和预览阶段不修改资产来源。
- 路径调整通过适配当前后端的官方接口完成，不直接拼改来源 JSON。
- 临时改绑前记录原路径；失败后若只涉及可独立恢复的来源字段，则恢复原值。
- 不能把“恢复来源字段”等同于“回滚导入器已修改的所有对象”。
- 导入失败后明确报告哪些对象可能已经变脏，不自动保存失败项，也不假装资产未发生任何变化。

### 8.5 仅更新，保存和版本控制交给用户

编辑器插件不调用资产保存接口，不弹出保存窗口，不主动签出。成功重导入后保留动画脏标记，并报告 Skeleton 和其他受影响包，用户检查后自行通过 UE 正常流程保存。

移除“允许签出”设置及目标包写入权限检查。磁盘只读不阻止内存更新，保存时的签出、锁定、冲突和权限处理交给 UE 与用户。插件设置的 Config 自动保存、用户主动导出报告仍保持不变。

不修改 UE 自动保存或其他工具的设置；执行时避免并行编辑或导入同一批资产。整批任务不是原子事务，取消不回滚已完成的内存更新，也不自动保存。失败后仍需检查受影响对象，必要时从版本控制恢复。

### 8.6 与 Auto Reimport 的协作

当前实现将自动重导入判定拆成“FBX 受监控”和“资产来源关联”两层。采集 `UEditorLoadingSavingSettings` 和 `UAutoReimportManager::GetMonitoredDirectories()`，通过 UE 的目录映射解析与 `DirectoryWatcher::FMatchRules` 复用通配符/导入格式过滤；按原生顺序处理重叠目录，未生效目录或不可见运行时规则不假定为启用。

来源关联按 `FAssetSourceFilenameCache` 的包目录相对及引擎基准相对路径语义评估所有来源记录，不使用插件路径映射或关键词候选作为原生关联证据。`.uasset` 目录本身不需要在监控范围内，没有单独的资产监控开关。仅“FBX 通过监控条件 + 资产真实来源关联”才显示资产已启用；需确认模式单独标识。

界面新增独立状态列、详细 Tooltip、每组启用数量和零匹配说明；CSV 增加状态与判断详情。每秒轻量观察活动目录及索引版本，变化时重算；开始更新或导出前复核当前元数据。该查询不加载资产或重复扫描全工程，报告中的原来源不因复核被覆盖。

UE 原生在配置变更后至少延迟 5 秒、并在空闲时才重建监控。窗口初次打开及范围/过滤规则变更后约 6 秒内报告“无法确认”，然后重新评估。公开接口不暴露实际运行时规则、重置完成信号或当前任务，因此观察期不是确认生效的握手；繁忙导致的延迟及第三方同目录覆盖仍有可见性限制。额外运行时目录没有可读规则时保持无法确认。

仅当本次勾选、可更新的行中存在已启用关联时，执行前额外提示重复更新及原生独立保存风险；不是只看总开关，也不把“已启用”当作“正在更新”。不修改用户全局设置，不暂停原生任务，不声称跨工具互斥。原生 Auto Reimport 的保存不受插件仅更新策略控制；状态、限制和测试见第一版使用说明。

引入该功能时新增 5 项 `ImportAssistant.AutoReimport.*` 测试，覆盖过滤、虚拟/重叠目录、来源关联、选择警告/分组和设置/元数据刷新，当时全量为 30 项；这些用例也包含在最近一次 51 项记录中。真实源文件变更触发原生任务的端到端行为仍待测试资产验收。

### 8.7 结果报告

至少区分：已更新未保存、导入失败、用户未选择、冲突未解决、来源未知、执行前变更、取消未执行。

保留每个 FBX 的结果分组和实际读取路径，支持复制或导出报告。不能仅依据某个返回值为真就忽略导入日志、后端错误和未保存提示。

## 9. 无编辑器窗口运行：第二阶段

### 9.1 可行边界

可以使用 `UnrealEditor-Cmd.exe` 和自定义 Commandlet，不显示编辑器窗口、不加载无关地图，只加载所需资产及依赖完成更新。

这仍然运行 UE 引擎、项目模块、导入器及序列化代码，需要匹配版本的引擎环境。完全脱离 UE 直接改写 `.uasset` 无法可靠处理导入数据、引用、压缩数据及版本差异，不属于本方案。

### 9.2 两阶段任务协议

建议提供只读检查和显式执行两个模式：

1. **检查模式**：接受 FBX、搜索范围和规则，输出候选与不确定项，不修改资产。
2. **执行模式**：接受已经确认的唯一资产—来源映射清单，重新验证后执行，不自动扩大更新范围。

清单记录工程标识、资产对象路径、实际 FBX、来源槽位、是否改绑和必要的状态信息；不信任过期快照，执行前再次核对。

### 9.3 实现要求

以下为尚未实现的独立 Commandlet 规划；当前编辑器更新队列不保存资产。未来无界面落盘需另外设计显式授权入口，不能直接复用为静默保存。

- 复用同一套索引、匹配、计划与执行逻辑，不复制第二套算法。
- Commandlet 入口不初始化 Slate 窗口。
- 明确等待注册表扫描、导入结果及相关编译/压缩任务完成后再保存和退出。
- 无界面模式禁止弹出需要人工选择的对话框，缺少配置时返回明确错误。
- 输出机器可读结果及明确退出码，区分完全成功、部分失败、计划冲突和运行失败。
- 避免编辑器和后台进程同时写同一批包；第一版外部执行要求关闭可能写入该工程的编辑器。
- 无界面运行也有进程启动、模块加载和扫描成本，尽量批量执行，而不是每个资产启动一次进程。

外部独立 GUI 可在后续消费检查结果并生成执行清单，不纳入第一版。

复用官方重导入并不自动保证所有手工编辑都原样保留。验收应记录不同后端的实际行为，明确哪些属于原生重导入固有行为，哪些需要工具阻止或提示。

### 10.3 性能测试方法

使用约 1 千、1 万、5 万条动画元数据规模及真实项目进行测试；纯匹配测试可以使用构造记录，但不能用构造记录代替真实注册表、磁盘和 UI 性能验证。

分别记录：

- 冷启动资产发现耗时。
- 首次索引构建耗时。
- 索引就绪后的源路径查询与关键词查询延迟。
- 主线程耗时峰值、P95/P99、最长无响应时间。
- 索引内存占用和更新成本。
- SSD 与网络源路径的差异。
- 结果数量大时的列表交互耗时。
- 单项与批量重导入耗时，和检索耗时分开统计。

初始验收目标：常见精确路径热查询约 100ms 内返回；插件可切分的主线程处理批次尽量控制在约 2–4ms；关键词检索可取消，窗口保持可响应。以上是待验证目标，不是已测性能或对底层单次调用的硬性保证。

完整性验收使用冻结工程状态下的独立基准清单，并在专门测试中允许加载资产核对真实来源；对指定范围内具有可靠来源的测试资产，要求漏检为零。未知来源单独统计，不计入“已确认不存在关联”。

## 12. 主要风险及应对

| 风险 | 应对 |
| --- | --- |
| 来源元数据缺失或不可信 | 当前显示未知并禁止不明确槽位执行；深入加载检查是后续增强，不伪造精确匹配 |
| 路径迁移导致误匹配或漏匹配 | 显式根目录映射，保留原路径和匹配依据 |
| 后台查询触及内存 UObject | 磁盘基线与主线程内存覆盖分离 |
| 扫描/索引建立期间发生变化 | 先订阅后快照、增量合并、版本控制和执行前复核 |
| Legacy 重导入阻塞主线程 | 串行队列、资产间取消、明确耗时边界；后续提供独立进程模式 |
| 不同资产配置被统一覆盖 | 对现有资产走原生重导入，逐资产使用原有导入数据 |
| 手工动画编辑被后端改变 | 按真实后端回归测试，记录限制，不承诺无条件保留 |
| 部分失败但界面误报完成 | 明确标记已更新未保存，逐项记录，展示未执行和失败项 |
| 自动重导入或外部进程竞争写入 | 执行前状态复核、串行协调、外部运行互斥约定 |
| 过度设计影响交付 | 单 Editor 模块、会话索引、第一版不做数据库和通用导入框架 |

## 14. 当前结论与后续决策

已经采用并实现“注册表元数据索引 + 源路径/关键词匹配 + 完整性可见的勾选式重导入”，补充名称模板、风险确认与结果交互。下一步是可恢复真实测试资产、导入后端和最新窗口人工验收，再根据测量优化性能；Commandlet 仍放在后续阶段。

本文件区分当前实现与后续方案；第一版操作和已知限制以使用说明为准。商业插件未实测，真实 FBX 重导入、窗口交互及规模性能验收仍待完成。对生产资产应先在可恢复样本上验证；工具只在用户主动执行后修改，存在来源改绑、脏覆盖或非主来源内容更新风险时另行确认，不代表每次普通主槽位同源干净更新都会弹框。
